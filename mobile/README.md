# اپلیکیشن هم‌قدم (SafeStep) — Flutter

اپ موبایل سامانه‌ی هم‌قدم؛ کاملاً فارسی، راست‌به‌چپ، با فونت وزیرمتن.

روی این ماشین با `Flutter 3.47.2` / `Dart 3.13.2` بیلد دیباگ اندروید گرفته شده است. `iOS` روی ویندوز کامپایل نمی‌شود؛ پوشه‌ی `ios/` برای ماشین مک آماده است.

---

## ۱. راه‌اندازی — گام به گام

### پیش‌نیاز

- `Flutter` پایدار ۳٫۲۲ یا بالاتر (این پروژه با ۳٫۴۷ آزموده شد)
- `JDK 17` و Android SDK (جزئیات نصب: `docs/phase2/00-toolchain.md`)

```bash
flutter --version
flutter doctor
```

زنجیره‌ی اندروید باید سبز باشد. قرمز بودن Visual Studio برای اپ ویندوز بی‌اهمیت است.

### گام ۱ — سکوها

اگر `android/` یا `ios/` نیست:

```bash
cd mobile
flutter create --platforms=android,ios --org ir.safestep --project-name safestep .
```

سپس موارد `PLATFORM_SETUP.md` را اعمال کنید (مجوزها، `usesCleartextTraffic` فقط برای توسعه، سرویس foreground، کلید نقشه از `MAPS_API_KEY`).

شناسه‌ی اندروید: `ir.safestep` — `minSdk 23` — `compileSdk 36` (الزام Flutter 3.47) — `targetSdk 34`.

### گام ۲ — وابستگی‌ها

```bash
flutter pub get
```

### گام ۳ — بیلد و اجرا

بک‌اند باید روی پورت ۴۰۰۰ باشد.

**بیلد دیباگ (معیار پذیرش روی ویندوز):**

```bash
flutter build apk --debug
```

خروجی: `build/app/outputs/flutter-apk/app-debug.apk`

**شبیه‌ساز اندروید:**

```bash
flutter run
```

آدرس پیش‌فرض API: `http://10.0.2.2:4000`

**گوشی واقعی (HTTP روی LAN):**

```bash
flutter run --dart-define=API_BASE_URL=http://192.168.1.20:4000
```

نقشه بدون `MAPS_API_KEY` خاکستری است، نه با پیام خطا. کلید را در محیط یا `android/gradle.properties` بگذارید؛ فایل‌های Firebase را هرگز کامیت نکنید:

- `android/app/google-services.json`
- `ios/Runner/GoogleService-Info.plist`

### تست

```bash
flutter test
flutter analyze
```

## ۲. ساختار پوشه‌ها

```
lib/
├── main.dart                 نقطه‌ی ورود؛ بارگذاری تنظیمات پیش از اولین فریم
├── app/
│   ├── app.dart              تم، محلی‌سازی، RTL، بزرگ‌نمایی متن
│   └── router.dart           مسیرها (go_router)
├── core/                     چیزهایی که همه‌ی feature‌ها استفاده می‌کنند
│   ├── accessibility/        تنظیمات دسترس‌پذیری + ابزار صفحه‌خوان و لرزش
│   ├── constants/            پیکربندی زمان ساخت
│   ├── theme/                رنگ، تایپوگرافی، فاصله، حرکت
│   ├── utils/                فارسی‌سازی، تاریخ شمسی، خطاها
│   └── widgets/              ویجت‌های مشترک
└── features/                 هر قابلیت، یک پوشه
    ├── splash/
    ├── onboarding/
    ├── auth/
    ├── home/
    └── settings/
```

هر feature در آینده سه لایه خواهد داشت: `data/` (تماس با API)،
`domain/` (مدل‌ها) و `presentation/` (صفحه‌ها و کنترلرها). در گام ۳ فقط
لایه‌ی نمایش وجود دارد چون هنوز داده‌ای از سرور نمی‌آید.

## ۳. قواعدی که در تمام کد رعایت می‌شوند

| قاعده | چرا |
|---|---|
| هیچ رنگ خام (`Color(0xFF...)`) در ویجت‌ها | حالت کنتراست بالا باید کل پالت را یک‌جا عوض کند |
| هر عنصر لمسی حداقل ۵۶ نقطه | کاربر با لرزش دست یا لمس کورکورانه |
| هر تصویر و آیکون تزئینی: `ExcludeSemantics` | وگرنه صفحه‌خوان معنا را دو بار می‌خواند |
| هر کارت قابل لمس: یک گره‌ی معنایی واحد | کاربر صفحه‌خوان با یک کشیدن ردش کند، نه چهار بار |
| هر انیمیشن از `AppMotion.of(context, ...)` | احترام به تنظیم «کاهش حرکت» سیستم‌عامل |
| ورودی عددی: تبدیل ارقام فارسی حین تایپ | صفحه‌کلید فارسی ارقام فارسی می‌فرستد |
| هیچ پیام خطای خام از شبکه به کاربر | «SocketException» برای کاربر بی‌معنا و ترسناک است |

## ۴. فونت

فایل‌های `assets/fonts/Vazirmatn-*.ttf` داخل مخزن‌اند و از شبکه دانلود
نمی‌شوند. دلیلش این است که اولین صفحه‌ای که کاربر می‌بیند نباید با فونت
پیش‌فرض سیستم رندر شود — که برای فارسی نتیجه‌ی بدی می‌دهد.

فونت وزیرمتن با پروانه‌ی SIL Open Font License منتشر شده و استفاده و
توزیعش در این پروژه آزاد است.

## ۵. محدودیت دستگاه

- روی ویندوز فقط `APK` اندروید بیلد می‌شود؛ آرشیو iOS نیاز به مک دارد.
- بدون کلید Maps نقشه خالی است.
- بدون `google-services.json` پوش نوتیفیکیشن Firebase در فاز بعد غیرفعال می‌ماند ولی بیلد باید موفق باشد.
- `usesCleartextTraffic` فقط برای HTTP محلی است؛ روی گوشی واقعی فایروال و IP میزبان را چک کنید.
- ردیابی پس‌زمینه روی برخی سازندگان اندروید (محدودیت باتری) نیاز به استثنای بهینه‌سازی دارد.
